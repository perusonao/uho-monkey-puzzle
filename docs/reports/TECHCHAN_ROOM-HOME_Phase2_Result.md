## 4. 実装内容（ビジュアル / 挙動）

### 4.1 部屋がより「生活空間」に見えるための調整
- `.closet`（クローゼット）を左上の空きスペースに追加し、SSOTの家具リスト（ソファ／テーブル／ベッド／テレビ／本棚／クローゼット／おもちゃ置き場）を満たす
- 観葉植物を1つ追加（`.plant2`、右上の窓脇）し、部屋の密度を上げる
- キャラクター幅を `34%→31%`（短い画面時 `29%→27%`）に縮小し、部屋全体が見えやすいよう調整

### 4.2 UIの被り（obstruction）軽減
- ステータスパネル: `width 29%→25%`、パディング・フォントを縮小、背景をやや透過（`#fffffff0→#ffffffe6`）
- 吹き出し: 位置を「窓の中央上」から「キャラクター右上」へ移動（`top18%,left39%,max-width55%` → `top15%,left54%,max-width42%`）し、窓が隠れないようにした

### 4.3 自発行動（アイドルAI）
- ユーザーが4アクション（ごはん／なでる／遊ぶ／ねる）のいずれも操作しない状態が **7秒** 続くと、てっちゃんが自分で家具スポットへ移動を開始し、以後 **9秒ごと** に次の行動へ切り替わる
- 行動選択はステータス優先: `げんき<35` → ベッドで休む／`おなか<35` → テーブルが気になる／`ごきげん<45` → おもちゃが気になる／それ以外は「ソファでくつろぐ」「おもちゃが気になる」を交互にローテーション
- 自発行動時のセリフ・状況テキストはユーザー操作時の反応文とは別テキストを用意し、「てっちゃんが自分から動いた」ことが分かるようにした（例: 「自分からソファに座って休んでいます」）
- ユーザーが4アクションのいずれかを押すと、進行中の自発行動タイマーを即座にキャンセルし、ユーザー操作の位置・セリフへ切り替わる（`resetIdleTimer()`）

### 4.4 ポーズ解決ロジック（pose resolver）
- `POSES` オブジェクトで実在するポーズ画像だけを `true` として管理（現状は `standing` のみ `true`、`sitting`/`eating`/`playing`/`sleeping`/`happy` は `false`）
- 行動種別ごとに「理想のポーズ」を `poseFor` で定義し、`POSES` に存在しないポーズは **リクエストを一切送らずに** `tecchan-standing.webp` へフォールバック
- そのため、座る／食べる／遊ぶ／寝る／喜ぶ専用の画像が用意されていない現時点でも、404は一切発生しない。将来的に該当ファイルを `assets/tecchan/` に追加し `POSES` の該当フラグを `true` に変更するだけで、コード変更なしに反映される設計

### 4.5 `prefers-reduced-motion` 対応
- `@media (prefers-reduced-motion: reduce)` で、キャラクターの移動トランジション（`left`/`bottom`/`transform`）とリアクション時の拡大（`.react`）を無効化

### 4.6 互換性・非対象範囲
- `localStorage` キー `tecchanGrowthV2` のスキーマ・読み込みロジックは無変更（既存セーブデータはそのまま動作）
- 既存の落下パズル関連ファイルには一切手を加えていない

- **画面幅**: 360x800 / 390x844 の両方
- **オーバーフロー**: 両サイズとも `scrollWidth`/`scrollHeight` が viewport と一致し、横スクロール・overflowなし
- **4アクション動作確認**: ごはん／なでる／遊ぶ／ねる のクリックで、位置・吹き出し・ヒント文言が変化することを確認（スクリーンショットで目視確認済み）
- **画像404 / JSエラー**: `console`・`pageerror`・HTTP 4xx応答（`favicon.ico` を除く）を監視し、両サイズとも検出なし
- **既存localStorage互換性**: `tecchanGrowthV2` に旧データ（`day:5, hunger:33, energy:20` 等）を注入した状態で再読み込みし、値が壊れずに反映され、JSエラーも発生しないことを確認
- **自発行動の遷移観測**: 「ねる」操作直後から390x844画面で5秒おきに `s.activity` をポーリングした結果、以下の遷移を観測（30秒間）:

  ユーザー操作（sleep）から自発行動（autoSofa）への切り替わり、および自発行動内での `autoSofa→autoToy→autoSofa` という異なる行動間の遷移を複数回確認し、「2回以上の自発的な遷移」の条件を満たした

## 7. 残課題

1. **専用ポーズ素材が未納品**: `tecchan-sitting` / `tecchan-eating` / `tecchan-playing` / `tecchan-sleeping` / `tecchan-happy` の実画像はまだ提供されていない。ポーズ解決ロジックは実装済みのため、画像を `assets/tecchan/` に追加し `POSES` の対象フラグを `true` にするだけで反映される。
2. **自発行動のタイミングはデモ向けの短さ**: 現在 7秒/9秒間隔としており、実運用（本番アプリ）としては長め（数十秒〜数分）に調整する余地がある。今回はPlaywrightでの動作確認を短時間で行うことを優先した値。
3. **部屋背景は引き続きCSS製**: `phase2-visual-target.png` のような実写風の部屋背景素材は今回も使用しておらず、既存のCSS製部屋のままである（指示により合成画像をそのまま背景に使うことは禁止されていたため）。
4. **クローゼット・着替えの機能連携なし**: クローゼット家具は視覚的に追加したのみで、サイドメニューの「着替え」機能とは未連携（Phase 2の指示範囲外）。
5. **自発行動によるステータス変化なし**: 自発行動は位置・セリフのみを変化させ、`hunger`/`mood`/`energy` の数値自体は変化させていない（ユーザーの能動的なお世話と区別するための設計判断）。将来的に「自発的にソファで休むと少しげんきが回復する」等の緩やかな効果を加える余地がある。
